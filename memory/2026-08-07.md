# 2026-08-07

## TUI Streaming Slow on Long Chats — FIX APPLIED (not yet committed)

**Issue:** During streaming with a very long chat, the TUI became slow.

**Key finding:** The complete fix already existed in commit `daed70e`
(`perf(tui): eliminate redundant string concat+Split in render pipeline`)
on branch `fix/goal-kickoff-deadlock`, but it was NOT merged into main.
MEMORY.md described it as done, but main still used the stock bubbles
`viewport.Model` with the `renderedBase` string + `SetContent`/`strings.Split`
anti-pattern (O(2n) per frame).

**What was applied to main (working tree, uncommitted):**
1. New `pkg/tui/lineviewport.go` — lightweight viewport optimized for large
   histories. `SetBaseLines`/`SetOverlayLines` (O(1) pointer swap) instead of
   `SetContent` (O(n) Split + findLongestLineWidth). `visibleLines()` uses
   `lineAt()` to pull only visible lines (O(visible) not O(total)). Cached
   `lipgloss.Style` in View().
2. `viewport.go` — `buildRenderedHistoryLines()` returns `[]string` directly
   (no string concat + strings.Split roundtrip). Per-message render cache
   (`msgRenderCacheLines map[string][]string` keyed by FNV-64a fingerprint).
   Single `GetHistoryView()` fetch per render cycle via pure helpers
   `countHistoryMessages`, `lastHistoryRoleFromHistory`,
   `cleanupStreamingIfCompleteWithHistory`. `renderedBase` string → bool flag.
3. `utils.go` — `messageFingerprint` (FNV-64a) helper.
4. `model.go` — `viewport` field type changed to `lineViewport`; cache cleared
   on session switch/width change.
5. `handlers.go` — follow-up tick after completeMsg to keep loading spinner
   from getting stuck; clear msgRenderCache on width change.
6. `types.go` — new `lineViewport` field + cache fields.
7. `perf_cache_test.go` — 6 new tests (fingerprint stability/sensitivity,
   countHistoryMessages, lastHistoryRoleFromHistory).

**Verification:** Applied patch cleanly to main (base 4f227b3 unchanged for TUI
files). `go build ./pkg/tui/...` OK, `go vet` OK, all pkg tests pass (only
`cmd/lele` fails due to missing `web/dist` build asset — pre-existing, unrelated).

**IMPORTANT / lesson:** The `daed70e` commit on `fix/goal-kickoff-deadlock`
was incomplete on its own — its viewport.go referenced helper functions
(`messageFingerprint`, etc.) that lived in `stash@{0}`. The fix was split
across an unmerged branch + an uncommitted stash. When porting, had to combine
both. Check `git stash list` and orphaned branches before assuming a fix is
merged.

**Status:** Applied to working tree, NOT committed. Full test suite green.
